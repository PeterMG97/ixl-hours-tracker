1. Executive System Overview

The Alstom IXL Team Hours Tracker is a specialized high-performance Single Page Application (SPA) designed to track, schedule, and reconcile daily engineering hours for multi-regional railway signaling teams in the Cairo and Istanbul engineering offices.

Key architectural goals:

  • Double-Entry Accounting Reconciliation: Project hours aggregated across the system strictly match individual team member hours at all times (Project Sum = Employee Sum).
  • Dual Office Calendars: Cairo (Friday/Saturday weekend) vs. Istanbul (Saturday/Sunday weekend) automated compliance.
  • Deterministic Zero-Framework Architecture: Vanilla ES6+, Semantic HTML5, and CSS3 with hardware-accelerated touch physics. Zero heavy build tools or framework overhead.
  • Zero-Emoji Standard: Strict corporate constraint prohibiting Unicode emojis across UI text, code symbols, test suites, and commit logs.

3.2 Composite Key Architecture

Allocations are keyed by composite strings formatted as ${employeeId}_${YYYY-MM-DD} (e.g. emp_22_2026-11-04).

To prevent string splitting bugs when employee IDs contain underscores (such as emp_22), keys are parsed using lastIndexOf('_'):

const lastUnderscore = key.lastIndexOf('_');
const empId = key.substring(0, lastUnderscore);
const dateStr = key.substring(lastUnderscore + 1);

4. Dual Office Calendar & Weekend Rules

Office Section Location Official Weekend (Holidays) Official Workdays
Applications - Cairo Cairo Friday (5), Saturday (6) Sunday through Thursday
ILS - Istanbul Istanbul Saturday (6), Sunday (0) Monday through Friday

Multi-Day Range vs. Single Weekend Overtime Rule

  • Multi-Day Range: When filling a date range that spans a weekend, the chosen holiday option is applied:
    • dayoff: Weekends are set to DAY OFF with 0h. Workdays get the project.
    • include: Weekends are worked and filled with project and hours.
    • skip: Weekends are untouched.
  • Explicit Single Weekend Day: If an engineer clicks a single weekend day (e.g. Friday in Cairo), the system permits direct overtime logging without forcing DAY OFF.

5. Desktop (PC) Interface Architecture

  • Excel-Style Grid Navigation: Arrow keys move the focused cell across days and employees. Enter opens the popover. Delete clears allocations.
  • Pointer State Machine:
    • Single Click: Stands on cell without opening popovers (cleans keyboard focus).
    • Double Click: Opens the Project Selection Popover.
    • 380ms Long Press: Enters 2D rectangular multi-cell selection.
    • 8px Jitter Deadband: Prevents micro-mouse tremors from accidentally entering drag mode.
  • Admin 2D Multi-Selection: In Peter MOUNIR's Admin Mode, multi-cell drag expands across multiple employee rows and dates simultaneously.

5.1 Employee Monthly Contributions Modal (#empContribModal)

Triggered by double-clicking any employee row on the schedule grid (Desktop) or via member contributions inspection (Mobile):

  • Daily Contributions Log Table (#contribDaysTable): Project / Task Contributed and Category columns render pure, clean, unhighlighted, uncolored text across Desktop and Mobile interfaces and Light and Dark themes (no green glowing pills, no colored borders, no background highlights), ensuring a distraction-free, professional corporate accounting log.
  • Day Status & Hours: Clean, uncolored indicators without bright green or blue text.

5.2 Dynamic Multi-Year Month Selection Engine

To support long-range planning across multi-year engineering projects without artificial ceilings, the application incorporates a dynamic multi-year month engine that allows selecting any month and any future year while strictly preserving the November 2026 start boundary:

  • November 2026 Invariant (APP_START_MONTH = '2026-11'): Earliest selectable boundary is locked to November 2026. Previous Month navigation arrow (#prevMonthBtn) prevents navigation prior to 11/2026. Date range inputs across Bulk Fill, Analytics, and Contributions modals enforce finalStart >= 2026-11-01.
  • Infinite Future Horizon: Pre-populated in markup with 170+ options from 11/2026 to 12/2040. When #nextMonthBtn reaches the last option, appendYearToMonthSelect(lastY + 1) dynamically appends subsequent years on demand (2041, 2042, 2050+).
  • Dual-Mode Responsive Labels (getMonthOptionLabel): Formats options dynamically based on device viewport. Desktop PC uses full month names with years (e.g. 11/2026 - November 2026 (Start), 08/2035 - August 2035), while Mobile uses compact 3-letter month formatting (e.g. 11/2026 - Nov (Start), 08/2035 - Aug).
  • Subsystem Synchronization: #auditMonthSelect, #contribMonthSelect, #projectMonthSelect, and #analyticsMonthFilterSelect dynamically inherit all future months from #monthSelect.

5.3 Special Action Separation & Exclusive Top Placement

To preserve clean project accounting semantics and eliminate duplicate action items from the searchable catalog, special allocation actions (DAY OFF, NO PROJECT, CLEAR/DELETE) are isolated from the standard project catalog:

  • Exclusive Top Row Placement (.quick-pill-row): Positioned as prominent, capital-letter, unhighlighted buttons at the top of each project selector surface (Cell Popover #cellPopover, PC Bulk Fill #bulkBrowseSection, and Mobile Logger #mobileBrowserContent).
  • Exclusion from Scrollable List (.project-pill-list): Special action items are completely removed from the scrollable list container across all interfaces, reserving the catalog strictly for genuine projects, tenders, and training/support accounting entries.
  • Active State Feedback: When an active cell or allocation holds Day OFF, NO PROJECT, or __CLEAR__, the corresponding top button dynamically displays .is-selected-proj selection styling.

  • Clean Empty State: The Activity Log table displays a clean descriptor (No edit history entries recorded yet.) when no logs exist.

To reduce visual clutter and provide an eye-pleasing working view, the desktop application incorporates a togglable key View (Month / Week) supporting both a 7-day week view and the full monthly grid:

5.8 Day Comments Engine & Cross-Interface Workflows

The Day Comments Engine enables team members and administrators to attach contextual remarks to allocations across PC and Mobile workflows:

  • Minimalist (+) Toggle Symbol: Represented uniformly by a simple, elegant (+) symbol button (.btn-comment-toggle) in monospace typography that expands an optional comment input field.
  • Single Day Fill (PC & Mobile): On PC cell popover (#cellPopover) and Mobile editor (#mobileLoggerCard) when Start Date equals End Date, assigns comment strictly to that single day.
  • Multi-Select Days (PC): Floating multi-select bar (#multiSelectBar) and cell popover in multi-edit mode allow assigning a comment across all selected days simultaneously.
  • Bulk Fill Date Range (PC & Mobile): Bulk fill modal (#bulkFillModal) and Mobile range filling assign comment across all workdays in that date range.
  • Visual Grid & Agenda Indicators: Desktop grid chips feature a subtle glowing cyan dot indicator (.chip-comment-dot) and comment text in hover tooltip (title). Mobile agenda displays italicized comment notes (.mobile-agenda-comment) beneath day labels.

10. Application Boot Sequence & Welcome Screen Resilience

The application employs a multi-tiered boot sequence to guarantee that the splash screen (#mobileWelcomeOverlay) never blocks entry or freezes:

  • Boot Order: initMobileWelcomeScreen() binds click, touch, keydown, and 10000ms auto-dismiss handlers at step 1 before any layout or data requests execute.
  • Inline Markup Fallback: The overlay element in index.html specifies an inline onclick handler that triggers CSS fade-out and unmounts the overlay even in the event of script loading interruptions.
  • Safety Fallback Timer: A lightweight inline script guarantees dismissal after 6000ms if no interaction occurs.
